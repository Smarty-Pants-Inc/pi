# Native input admission (version 1)

A user input can be awaiting an extension handler without being in a steering or follow-up queue yet. An idle check alone used to miss that input: a host could replace the session, then receive success for input enqueued into the disposed session.

Version 1 accounts for that phase natively and refuses unsafe replacement. It does not replay or silently transfer input between sessions.

## Detect the running host

- SDK: `session.capabilities.inputAdmission === 1`.
- Extensions: `pi.hostCapabilities.inputAdmission === 1`. Do not infer the running host's guarantee from an extension's separately installed package export.
- RPC: `get_state.data.capabilities.inputAdmission === 1`.
- `HOST_CAPABILITIES` is also exported for package-level detection.

`session.inputAdmissionCount` counts inputs awaiting native handoff. Admission starts synchronously at entry to `prompt()`, `steer()`, `followUp()`, and `sendUserMessage()`, before any asynchronous input handler, command lookup, image processing, auth or preflight. It ends on actual queue/run handoff, handled short-circuit, or failure. Commands own their input once their handler is dispatched, so commands can replace sessions without fencing themselves. A nested triggered custom message transfers only its own content: its run and settlement do not release the originating user input's admission. That held input stays accounted for and cancellable until its own handoff, handled completion, or refusal.

While admission is pending, `isIdle` is false, `isPromptPending` is true, and `pendingMessageCount` includes the admission. `getSteeringMessages()` and `getFollowUpMessages()` remain actual queue contents. A queued message can wait for a later prompt even when no run is active; check pending counts as well as idle. Extension `ctx.hasPendingMessages()` includes admissions. Settlement-deferred inputs remain accounted for until their native handoff; scheduling alone does not resolve their SDK result or acknowledge them. SDK `prompt()` and `sendUserMessage()` called from an active `agent_settled` handler refuse immediately with `INPUT_ADMISSION_BUSY`: their delivery would otherwise wait for that same handler to return. Submit SDK input after settlement instead. Extension `pi.sendUserMessage()` remains detached, so settlement handlers can schedule a turn without awaiting their own completion.

RPC state includes `inputAdmissionCount`, `inputsFenced`, `isIdle`, and `isPromptPending` alongside existing fields. Input responses are authoritative: success is emitted only after handling or native handoff; failed admission never gets a success response. `RpcClient.prompt()`, `steer()`, and `followUp()` reject failed responses.

## Fence replacement

```typescript
const release = await session.fenceInputs();
try {
  // Input is already closed, including across asynchronous host lifecycle work.
} finally {
  release();
}
```

`fenceInputs()` closes admission synchronously, before its returned promise can yield. It refuses immediately with `InputAdmissionError.code === "INPUT_ADMISSION_BUSY"` if any admission, active settlement, submitted mode-owned input, or undelivered native queue exists. This is a bounded zero-wait refusal; the old session stays open and usable. Settle the input or explicitly recover queues before retrying. It does not wait indefinitely for extension handlers or initiate model work to drain a queue.

After successful acquisition, new inputs reject with `INPUT_ADMISSION_FENCED`. Release reopens an unchanged session after cancellation/failure; it cannot release another operation's fence. Disposed sessions stay sealed and reject `INPUT_ADMISSION_DISPOSED`, even after release.

`AgentSessionRuntime.newSession()`, `switchSession()`, `fork()`, `importFromJsonl()` and `dispose()` hold this fence through before-switch/fork, abort/persistence, shutdown hooks, final disposal, and replacement completion. Runtime lifecycle ownership also covers the receiving factory, publication, setup, rebind, and `withSession` completion. Overlapping external replacement/disposal refuses with `INPUT_ADMISSION_BUSY` before mutation, even when the outgoing session has already been disposed. External input remains fenced until initialization finishes; awaited rebind/`withSession` callbacks can still submit callback-owned input to the receiving session. Detached descendants lose that permission when their callback returns. A rejected replacement is not a completed replacement. Do not bypass a busy refusal with direct session-manager mutation or raw agent methods. Native owner-allocation restrictions remain unchanged.

`AgentSession.dispose()` is synchronous and refuses active, admitted or queued work. First `await session.abort()` (which rejects still-admitted input with `INPUT_ADMISSION_ABORTED`), recover undelivered input if necessary, then dispose. Aborted hook completions cannot enqueue later. Runtime disposal performs the active-run abort/persistence itself after acquiring the fence. Its optional `beforeShutdown` callback runs inside that fence, for asynchronous host terminal teardown.

Orderly shutdown hosts may explicitly choose rejection instead of busy refusal with `fenceInputs({ rejectQueuedInput })` or `runtime.dispose({ rejectQueuedInput })`. Admission closes before abort yields, pending input rejects with `INPUT_ADMISSION_ABORTED`, and the synchronous callback receives every undelivered native message before queues are cleared. The callback must return only after issuing its authoritative receipt; a throwing callback leaves the queues intact and reopens admission. Explicit orderly shutdown also cancels the wait on outstanding `agent_settled` hooks and joins native settlement before issuing queue receipts. Arbitrary non-dialog extension promises are not forcibly terminated: their results remain observed and late input is rejected by the retiring session's fence/disposal. This cancellation does not change ordinary `abort()` or replacement's immediate busy-refusal policy. No input is implicitly replayed. `agent.getQueuedMessages()` snapshots both complete queues, independent of queue delivery mode.

Terminal owners use `runtime.dispose({ terminal: true, rejectQueuedInput })`, distinct from an ordinary recoverable disposal. This permanently seals admission, aborts owned bash before joining responses, and cancels startup, dispatched extension commands and active lifecycle waits with `INPUT_ADMISSION_SHUTDOWN`. Ordinary concurrent lifecycle calls still refuse immediately. Non-cooperative promises remain observed but their receiving runtime cannot be published after cancellation; any late unpublished queues are returned through the rejection callback with their owning session as its second argument. Terminal shutdown hooks get a one-second cleanup deadline, including when a signal upgrades an already-running ordinary shutdown. Expiry cancels dispatch, prevents subsequent cleanup handlers from starting, and records a `cleanup incomplete` warning in `runtime.diagnostics` plus a `session_shutdown` extension error for host reporting. Mandatory native invalidation/teardown still completes; already-running arbitrary promises may finish without launching further handlers. Native `turn_end` and `agent_before_settle` waits are cancelled too: late boundary drafts and continuation requests are discarded, and a cancelled turn ends before consuming undelivered queues. Fence release retains the cancellation controller of any settlement that began while the fence was held. Arbitrary extension code is not forcibly terminated; captured session and UI authority is invalidated when disposal finishes.

The TUI renders a busy refusal without exiting, preserves input submitted after a fence in the editor, and does not stop the terminal before admission fencing succeeds. Enter and Alt+Enter use the same admission/recovery policy. A rejected submission is appended to any newer editor draft or recovered queued text rather than overwriting it. Extension-requested shutdown remains pending and is rechecked after native settlement or admission completion, including handled startup input that starts no run and receiving-session lifecycle completion. Escape also cancels admission before streaming starts. Recovery expands collapsed paste content before replacing editor state. Complete queued images are retained in memory behind editor markers and reattached when the user submits the recovered text, including first-prompt and queued-tail transfers after compaction; removing a marker discards that attachment from the submission. Signal shutdown cancels/rejects input explicitly, joins outstanding compaction transfers before final recovery, preserves unsent collapsed paste content, and prints the complete recovered draft and images after terminal cleanup.

## RPC shutdown receipts

Orderly stdin EOF fences and aborts before joining command-response work, including during startup draining. Extension-requested shutdown and SIGTERM/SIGHUP use the same orderly shutdown path. Still-admitted input gets its correlated failure response; SIGTERM/SIGHUP also return one correlated `INPUT_ADMISSION_SHUTDOWN` refusal for each unprocessed startup command before exit. EOF during initial binding cancels dialogs and allows a 100 ms cooperative binding window to dispatch the already-received startup backlog; a non-cooperative binding is then cancelled and its backlog receives terminal refusals. Native input is then fenced/aborted before joining its results. Already-started non-input command responses are joined inside the shutdown fence before session invalidation. Mode-owned terminal cancellation also bounds prompt/command work retained across replacement, with exactly one correlated response; commands can still intentionally replace their own session. A bash hook that completes after its captured session is retired cannot execute or persist its result. Fatal startup overflow starts cancellation immediately and refuses the already-buffered correlated commands before flushing and exiting. `RpcClient.promptAndWait()` cancels its event collector on submission failure, so recoverable refusal leaves no orphan listener, timer, or rejection. Already acknowledged but undelivered queued input is returned before disposal as `RpcInputRejectedEvent`:

```json
{"type":"input_rejected","reason":"shutdown","sessionId":"outgoing-session-id","error":"INPUT_ADMISSION_SHUTDOWN: queued input was not delivered","messages":[{"role":"user","content":[{"type":"text","text":"queued instruction"}],"timestamp":0}]}
```

`messages` contains the complete queued content, including image attachments. This is an authoritative terminal rejection receipt, not a success or an instruction to replay automatically. `RpcClient.onEvent()` exposes it and keeps reading through orderly `stop()` shutdown. When a process exits without closing inherited output pipes, `RpcClient` allows one second for final receipt drainage, then rejects outstanding requests with the known exit failure and makes `stop()` report incomplete output drainage. It does not claim receipt completeness after that deadline. Hard kills, crashes, transport loss, or a client force-kill timeout are not orderly shutdown guarantees; consumers still need their existing failure/no-replay protections.

## Integration gate

A host must detect version 1 on the reviewed installed runtime, consume state, busy refusals and terminal rejection receipts, then prove its own rotation and continuity behavior. This runtime contract alone does not authorize removing a production hold or bypassing independent owner acceptance gates.
